# Ayato Intelligence Engine - 技術要件定義書 (Technical Specifications)

## 1. 動作基盤 (Infrastructure)
- **Runtime**: Google Cloud Run Jobs (GCP)
- **Execution Schedule**: Cloud Scheduler による1日2回定期実行 (日本時間 05:00 / 17:00)
- **Package Manager**: uv (Python 3.12)
- **Logging**: Loguru による構造化JSONログ (Cloud Logging に最適化)
- **Secret Management**: Google Cloud Secret Manager より実行時注入

## 2. 永続化レイヤー (Persistence)
- **Database**: Supabase (PostgreSQL)
- **Storage Strategy**: 生成されたレポートアーティファクトは Supabase の `generated_reports` テーブルへ保存し、それらをトリガーに `ayato_studio_portal` へ配信する。ローカルファイルストレージは一切使用しない。

## 3. 知性生成エンジン (AI Engine)
- **Model SDK**: `google-genai` (公式 SDK)
- **Execution Target**: AI＆半導体分野 (`tech`)、および週次コラム (`weekly`) の2つのプラグインのみを稼働。その他（金融・エネルギー）はディスカバリ段階で無効化。
- **Analysis Strategy**:
    - **Scoring**: `tech_score_v1.txt` プロンプトによるAI/技術情報の定量インパクト評価（0-100）。
    - **Generation**: `tech_report_v1.txt` による極小ノイズ要約。
    - **Language**: **日本語（jp）のみを出力**（英語 generation を廃止し、APIコストと実行時間を削減）。
- **Distribution**: 
    - `tech` エンジンの正常完了時に限り、GitHub Actions 経由で `ayato_studio_portal` の再構築トリガー（`rebuild-portal`）を自動送信。

## 4. 開発・品質管理 (Quality Assurance)
- **Linter/Formatter**: Ruff (ルール準拠、CI自動修正禁止)
- **Testing**: Pytest (Asyncio-mode)によるインフラ境界・DIモックテスト
- **CI/CD**: GitHub Actions による Cloud Run Job の自動ビルド・デプロイ (`deploy.yml`)
