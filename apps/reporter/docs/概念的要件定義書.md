# Ayato Intelligence Engine - 概念的要件定義書 (Conceptual Requirements)

## 0. 序文：知性のマニフェスト
本システムは、情報の洪水から「意味」を救い出し、自律的な知性を構築するための実験場である。
我々が目指すのは、単なるニュースの要約ではない。世界中に散らばるニッチな情報の「脈動（Pulse）」を捉え、それらを繋ぎ合わせて「線（Strategy）」へと昇華させる、デジタルな思考回路の構築である。

---

## 1. 戦略的ポジショニング：感覚器官から思考器官へ
本エンジンは、二つの時間軸と二つの役割を使い分けることで、独自価値（Alpha）を創出する。

### 1.1 Pulse (Flow) - 感覚器官としての速報
*   **役割**: 世界の最先端AI論文（arXiv cs.AIコアカテゴリ）およびAI/半導体ニュースを監視する。
*   **思想**: 瞬間の技術的ブレイクスルーや異常を捉えることに特化する。大手メディアが報じる前の「予兆」を逃さない。
*   **AI・半導体特化**: 旧来存在した金融やエネルギーなどのマクロデータ収集は一時停止し、本ドメインのアイデンティティである「AIインテリジェンス」へ全リソースを集中させる。
*   **日本語専用化**: 英語の並行生成を廃止し、日本のエンジニア・ビジネスリーダーに向けて「最も解像度の高い日本語による知性要約」を生成することに特化する。

### 1.2 Deep Analysis (Stock) - 思考器官としての深層分析
*   **役割**: 蓄積された「点（速報）」の情報を時間軸で繋ぎ合わせ、中長期的な「線」のシナリオを提示する。
*   **思想**: 単発のニュースはコモディティである。過去の予測と現在の結果の「乖離」をAIに考察させ、週次等のタームで週次インテリジェンス・コラム（`weekly`）として再合成する。

---

## 2. 知性の品質管理：Quality is the Only Currency
情報は量ではなく、質（スコア）によってのみ定義される。

### 2.1 厳格なフィルタリング
*   **思想**: 独自性のない、あるいは重要度の低くなった情報は「ノイズ」として切り捨てる。
*   **非実装（Why Not）**: 汎用的な大手ニュースのアーカイブは行わない。ストレージの浪費であり、知性の純度を下げるためである。

### 2.2 Diversity Guard（多様性の保護）
*   **思想**: スコアリングは絶対ではない。特定の地域やドメインに情報が偏ることは、知性の「盲点」を生む。
*   **実装（What）**: 米国や日本だけでなく、欧州、中国、アジアなどの地域バケットを定義し、たとえスコアが基準値に達していなくても、その地域の「代表」として情報を拾い上げるロジック（Diversity Guard 2.2）を保持する。

## 3. 開発・運用の美学：GCP-Native Professionalism
システムの挙動は、その実行基盤と不可分である。

### 3.1 GCP環境への絶対的信頼
*   **思想**: **「GCP（Cloud Run / Supabase）で実行されること」**をすべてのロジックの前提とする。
*   **非実装（Why Not）**: ローカル専用のDBフォールバックや便利機能は実装しない。
*   **理由**: 環境の乖離（ドリフト）は、隠れたバグと運用コストの温床となる。ローカルはあくまで「本番を映す鏡」であるべきだ。

### 3.2 自律型リビルドと結合の最小化
*   **思想**: ポータルの更新は、意味のある情報が生成されたときにのみ行う。
*   **実装（What）**: `tech`（AI＆半導体）プラグインの処理が成功完了した時のみ、GitHub Actionsへポータルの再ビルドイベントを送信する。不要な実行や他プラグインのテスト実行時はトリガーをバイパスし、無駄なビルドコストと環境への負荷を削減する。

### 3.3 開発者の知性と責任
*   **思想**: コード品質はツールに押し付けるものではなく、開発者が自ら獲得するものとする。
*   **非実装（Why Not）**: CI側での自動修正（`--fix`）は行わない。
*   **理由**: エラーは「警告」であり、学びの機会である。自動修正による無自覚な変更は、システムの透明性を損なう。

## 4. リポジトリ・ガバナンス：SV-COS (Single-Vendor Open Source)
本プロジェクトは、ソースコードを公開しつつも、その決定権と商業的価値を Ayato Studio が 100% 保持する戦略を採用する。

### 4.1 強いコピーレフト (AGPL-3.0)
*   **思想**: 「知性のタダ乗り」を許さない。
*   **理由**: 本システムをフォークして SaaS として公開する者には、同一ライセンスでの公開を義務付ける。これにより、競合他社による「隠れた商用利用」を構造的に抑止し、商用ライセンスの販売という選択肢（デュアルライセンス）を維持する。

### 4.2 コントリビューター合意書 (CLA) の必須化
*   **思想**: 著作権の分散は決定権の喪失である。
*   **理由**: 外部からの PR をマージする際、著作権の利用許諾を Ayato Studio に集約する。これにより、将来的なライセンス変更や M&A 時の障害を排除し、永続的な決定権を担保する。

### 4.3 商業的価値の保護 (COMMERCIAL.md)
*   **思想**: オープンソースは慈善活動ではなく、エコシステムの構築である。
*   **方針**: 商用利用の境界線を明確に引き、ビジネス価値を毀損させない。

## 5. 拒絶のリスト（Do NOT Implement）
我々が「やらないこと」は、我々が「何者であるか」を定義する。

1.  **マルチプラグインの野放しな自動実行**: AI特化の決定に基づき、`finance` や `energy` などの非AIプラグインはディスカバリから除外し、自動実行対象から排除する。
2.  **英語併記によるオーバーヘッド**: 日本のターゲット読者に絞り、英語レポートの同時ビルドを行わない。
3.  **無駄な再ビルドループ**: 意味のあるデータ更新がない状態での、ポータルの定期リビルドやポーリング監視は行わない。

## 6. 未来 of 展望
`ayato_reporter` は現在、情報を集める「感覚器官」として機能している。
次のフェーズでは、集めた記憶を再合成し、人間では不可能な規模で推論を行う「思考器官（Brain）」の実装へと向かう。この進化において、本ドキュメントに記された哲学は、すべてのコード変更の羅針盤となる。
