# ADR 0007: 台本直接受領型AI動画生成システムとプロンプト・RLHFデータ収集アーキテクチャ

## 1. 状態 (Status)
提案中 (Proposed)

## 2. 背景・文脈 (Context)
- `AI_Agemt/動画生成` で構築された画像生成・音声合成・動画結合の自動化パイプラインを、Web 上で一般ユーザー向けに公開したい。
- LLM による台本自動生成は行わず、ユーザー自身が作成した台本データ（シーンごとのナレーションおよび画像生成プロンプト）を直接受け取って動画化する特化型システムとする。
- これにより、サーバー側のLLM推論コスト・トークン消費を完全にゼロにしつつ、ユーザーが作成した質の高い台本・プロンプトデータおよび評価リアクション（いいね / Bad）を自社の学習・データセット資産として Supabase に蓄積する。
- 自社の計算コスト（画像生成・音声合成）は外部無料API/クライアントを活用し、利用規約およびプライバシーポリシー上でデータの二次利用・学習利用・第三者提供の許諾を明記して法的健全性を確保する。

## 3. 決定事項 (Decision)
1. **台本生成ロジックの排除と台本受領特化（減算の美学）**:
   - LLM による自動台本生成は実装せず、ユーザーからの構造化台本（JSONまたはシーン入力）の直接受領・バリデーションに特化する。
2. **外部無料/OSSプロバイダーへの計算リソース委託**:
   - 画像生成: Pollinations.ai (無料REST API)
   - 音声合成: gTTS (無料Google翻訳TTS) / Web Speech API
3. **Ayato Studio モノリポへの機能統合**:
   - フロントエンド: `apps/web/src/app/apps/video-generator` 配下に台本受領・動画プレビューUIを実装。
   - バックエンド/コア: `apps/video-engine` に Python 3.12 パイプラインを配置。
4. **Supabase への台本＆RLHF評価ログ蓄積**:
   - `video_generation_logs` テーブルに、セッションID、入力された台本データ（プロンプト・テキスト）、評価リアクション（like / dislike）、メタデータを記録。
5. **利用規約 (Terms) および プライバシーポリシー (Privacy) の改定**:
   - 使用している外部AIサービスの明記。
   - 入力された台本・プロンプトデータおよび評価情報が、サービス改善・AIモデル学習・研究・データセット提供等に利用される旨の同意条項を追加。

## 4. 採用理由 (Why)
1. **極限のコスト削減とシステム単純化（減算の美学）**:
   - LLM API（OpenAI / Gemini等）の常時呼び出しが不要となり、API障害リスクやトークン費用を完全排除できる。
2. **純度の高い高品質データセットの直接収集**:
   - ユーザーが意図を持って作成した生きた台本・画像プロンプト・ナレーション文、およびそれに対する評価リアクションがそのまま手に入るため、自社ファインチューニング用の教師データとしての価値が最大化される。
3. **高速なレスポンス**:
   - 台本生成の待ち時間（数秒〜十数秒）が不要となり、入力即座に画像・音声の生成プロセスへ遷移できる。

## 5. 不採用理由 (Why Not)
- **サーバー側でのLLM自動台本生成**:
   - APIコストが発生し、ユーザーの意図と乖離した台本が生成された場合の離脱やリトライによる無駄な負荷が増大するため不採用。
- **データ非収集運用**:
   - 自社プラットフォームの成長資産（プロンプト・RLHFデータ）が蓄積されないため不採用。

## 6. 結果・影響 (Consequences)
- **メリット (Positive)**:
   - 最低限のコード量とゼロAPIコストで、堅牢かつ高速な動画生成ツールを公開できる。
   - ユーザーから直接提供される高精度な台本・プロンプトデータを Supabase に蓄積できる。
- **トレードオフ / 注意点 (Negative / Risks)**:
   - ユーザー側で台本（またはシーン情報）を用意する必要があるため、テンプレート（サンプル台本ボタン等）を用意して入力ハードルを下げる工夫が必要。
