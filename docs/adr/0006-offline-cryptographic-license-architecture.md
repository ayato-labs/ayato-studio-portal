# ADR 0006: 完全オフライン・非対称暗号署名ライセンスキー（Ed25519）アーキテクチャの採用

## 1. 状態 (Status)
承認 (Accepted)

## 2. 背景・文脈 (Context)
- Ayato Studio のソフトウェア（`Transform_MovieToText`, `TenKOrbit`）の最大のコア価値は、**「完全オフライン動作・1バイトも外部に送信しないエアギャップ保証」** である。
- 従来の SaaS が採用する「起動時や利用時に毎回クラウドサーバーに API 問い合わせを行うオンライン認証（DRM）」を採用した場合、ネット回線を切断した環境（機内・閉域網・出張先）でアプリが動作しなくなり、最大の差別化要因が根底から崩壊してしまう。
- そのため、**「インターネット通信を一切行わずに、ローカル完結で改ざん不可能な Pro 権限アンロックを行うライセンス認証技術」** が不可欠となる。

## 3. 決定事項 (Decision)
1. **非対称暗号（Ed25519）によるオフライン・ライセンス署名方式の採用**:
   - **サーバー側（Webポータル / Stripe Webhook）**: サーバーのみが保持する「秘密鍵（Private Key）」で、`{ email, productId, planType, expiresAt }` のペイロードに署名し、Base64 / 英数字フォーマットのライセンスキー（例: `AYATO-MTT-xxxx-yyyy-zzzz`）を発行する。
   - **クライアント側（デスクトップ / Android アプリ）**: 配布バイナリ内に「公開鍵（Public Key）」のみを埋め込む。
   - **認証処理**: アプリは外部通信を一切行わず、公開鍵を用いてローカルで数学的に署名を検証（Verify Signature）する。
2. **フリーミアム（無料枠）と Pro 機能のコード内ゲーティング（Feature Gating）**:
   - アプリ起動時、ローカル SQLite または設定ファイルに有効な署名済みライセンスキーが存在しない場合は「Free モード」、有効な署名が検証された場合は「Pro モード」として全機能をアンロックする。

## 4. 採用理由 (Why)
- **「0バイト外部送信」の絶対的維持**:
  - ライセンス認証のためにサーバーへ通信する必要が物理的に 0 になり、金融・法律・医療などの最高度機密環境でも胸を張って販売できる。
- **改ざん・クラックへの強力な数学的耐性**:
  - 秘密鍵がサーバーにしか存在しないため、第三者が勝手にライセンスキーを偽造・生成することは現代の計算機科学上不可能。
- **インフラコスト 0 円（減算の美学）**:
  - ライセンス認証専用の常駐データベースや認証サーバーを保守する必要がなく、サーバーレスで完全に完結する。

## 5. 不採用理由 (Why Not)
- **[オンライン常時問い合わせ型 DRM]**:
  - 却下理由: オフライン環境で使えなくなり、プロダクトのアイデンティティ（エアギャップ保証）を喪失するため。
- **[単純な固定文字列パスワード方式]**:
  - 却下理由: パスワードが 1 つ流出しただけで全員が無料で使えてしまい、ライセンス管理が破綻するため。

## 6. 結果・影響 (Consequences)
- **メリット**:
  - 無料版として全世界に配布しつつ、有料顧客には Stripe 決済後にワンクリックでライセンスキーを発行し、完全オフラインで Pro 機能を安全にアンロックできる。
