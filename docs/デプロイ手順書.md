## 2. 通常リリース・デプロイ手順（日常の運用）

### ステップ 1: ローカル検証とビルド確認
コード変更後、必ず各リポジトリでテストおよびビルドが通ることを確認します。

```powershell
# 1. ポータル側のビルド検証
cd c:\Users\saiha\My_Service\programing\ayato-studio\main-web-tech-ai
npm run build

# 2. 収集バッチ側のテスト検証
cd c:\Users\saiha\My_Service\programing\ayato-studio\ayato_reporter
uv run pytest
```

### ステップ 2: フィーチャーブランチの作成とコミット
Conventional Commits 規約に従ってコミットを作成し、リモートへプッシュします。

```powershell
# ポータル側
git checkout -b feat/your-feature-name
git add .
git commit -m "feat: add your new feature"
git push -u origin feat/your-feature-name
```

### ステップ 3: プルリクエスト（PR）の作成とマージ
1. GitHub リポジトリ（`ayato-studio-portal` または `ayato-reporter`）にて、`main` ブランチ向けのプルリクエストを作成。
2. CI テストの通過を確認後、PR を `main` ブランチへマージ（Squash and merge または Rebase and merge）。

### ステップ 4: 自動デプロイの確認
- **Cloudflare Pages**: マージ完了後、約1〜2分で自動ビルド・デプロイが完了し、`https://ayato-studio.ai` に反映されます。
- **Cloudflare Dashboard**: `Pages` > `ayato-studio-portal` > `Deployments` にて「Success」を確認。

## 3. データベース・マイグレーション適用手順 (Supabase)

新しいテーブルやカラムを追加した際の手順です。

1. **マイグレーションSQLの確認**:
   - `docs/migrations/` 配下に格納された最新の SQL ファイル（例: `001_create_ai_news_table.sql`）を開きます。
2. **Supabase ダッシュボードへのログイン**:
   - [Supabase Dashboard](https://supabase.com/dashboard) にアクセスし、該当プロジェクトを選択。
3. **SQL の実行**:
   - 左側メニューの `SQL Editor` をクリック。
   - `New query` を作成し、SQL ファイルの内容を貼り付けて `Run`（実行）をクリック。
4. **反映確認**:
   - 左側メニューの `Table Editor` にて、新しいテーブルおよびカラムが正常に作成されていることを確認。

## 4. 収集バッチ（`ayato_reporter`）の GCP デプロイ手順

バッチ処理のコンテナイメージを GCP Cloud Run Job へ手動/自動デプロイする際の手順です。

### 前提条件: gcloud CLI の認証
```powershell
cd c:\Users\saiha\My_Service\programing\ayato-studio\ayato_reporter
gcloud auth login
gcloud config set project <YOUR_GCP_PROJECT_ID>
```

### Cloud Run Job のビルドと更新
```powershell
# Cloud Build を用いたイメージビルドとJobへの反映
gcloud builds submit --tag gcr.io/<YOUR_GCP_PROJECT_ID>/ayato-reporter:latest .

# Cloud Run Job の更新
gcloud run jobs update ayato-reporter-job \
  --image gcr.io/<YOUR_GCP_PROJECT_ID>/ayato-reporter:latest \
  --region asia-northeast1
```

### 手動実行テスト
```powershell
gcloud run jobs execute ayato-reporter-job --region asia-northeast1
```

## 5. 緊急ロールバック手順 (Troubleshooting)

### A. フロントエンドの即時切り戻し
1. [Cloudflare Dashboard](https://dash.cloudflare.com/) にログイン。
2. `Workers & Pages` > `ayato-studio-portal` > `Deployments` を開く。
3. 安定稼働していた直前のデプロイ履歴を探し、右側の `...` メニューから **「Rollback to this deployment」** を選択。
4. 数秒で全世界のエッジが直前の正常バージョンに切り戻されます。

### B. バッチ処理の停止
GCP Cloud Scheduler にて一時的にジョブの実行を「一時停止（Pause）」に設定します。

## 6. 環境変数・シークレット一覧

| プロジェクト | 設定場所 | 主要シークレット名 |
| :--- | :--- | :--- |
| **`ayato_studio_portal`** | GitHub Secrets & Cloudflare Pages | `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_GA_ID` |

> [!CAUTION]
> 秘密鍵・`.env` ファイルは絶対に変更・コミットしないでください。すべて `.secrets/` または Secret Manager で管理します。
